# frontend/ — Nivis registry SPA (focused fork of registry-ui)

A **focused fork of [`opentofu/registry-ui`](https://github.com/opentofu/registry-ui)**: it keeps
that project's architecture and contract model, and adapts the resource-page rendering to show
**Nix constructors** instead of scraped HCL. It is **data-agnostic** — it consumes a JSON contract,
so it works against our static contract with no live backend (v1) and the later API unchanged.

## License & provenance

Upstream `opentofu/registry-ui` is **MPL-2.0** (Mozilla Public License 2.0), which permits forking
and redistribution provided modified MPL-covered files keep the license and notice. This fork is a
clean-room reimplementation on the same stack (it does not copy upstream source files); the design,
contract types, and routing model follow registry-ui. The contract type definitions in
`src/lib/contract.ts` mirror upstream's `backend/internal/server/openapi.yml`
(`ProviderVersion` / `ProviderDocs` / `ProviderDocItem`), extended with the Nivis `compat` record.

## Stack

React 19 + Vite + react-router (HashRouter, for static hosting) + TanStack Query + Tailwind, built
with pnpm — all available in the repo's `nix develop` shell.

## What is kept vs adapted

**Kept:** the data-agnostic SPA model, the `index → provider → item` routing, the contract types,
TanStack Query for data loading.

**Adapted:** `src/pages/ResourcePage.tsx` renders the **Nix-constructor** document bodies the
generator emits (signature, typed required/optional arguments, computed outputs via `refAttr`) — it
contains **no HCL `resource {}` block**. `src/components/CompatBadge.tsx` surfaces the four-axis
compat record honestly (`compatible by design` vs `e2e verified`).

**Wired:** `src/lib/data.ts` points at the static contract under `registry/docs/providers/...` (plus
`registry/catalog.json`). In dev and the v1 deploy these are plain files; the later API serves the
same paths, so this layer does not change.

## Build & run (inside `nix develop`)

```sh
# Generate the contract into public/ first (from the repo root):
cd tools && go run ./cmd/generate -extract <extract-out> -contract ../frontend/public

cd frontend
pnpm install      # esbuild build is approved in pnpm-workspace.yaml
pnpm test         # vitest: markdown parser + ResourcePage render (no-HCL) tests
pnpm build        # tsc -b && vite build -> dist/ (self-contained static site)
pnpm dev          # local dev server
```

`pnpm build` emits a self-contained static `dist/` with the contract bundled — ready for S3 +
CloudFront. The generated contract under `public/registry/` and `dist/` is a build artifact
(gitignored), regenerated by `tools/generate`.
